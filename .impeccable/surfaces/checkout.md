## Approved contract

WORLD: existing Hanken typography, configured pale background, ink, accent, square fields/actions and fine rules. User explicitly approved the direction then requested the real Forms manager appearance. Use FormTextControl/MUI and site theme, never a separate field system or hardcoded client palette. Full existing SiteHeader is unchanged.
FIRST VIEWPORT: complete header, thin Store subheader, drawn three-step progress, open form column and stable product-photo/amount recap. On mobile, compact recap above the form, full-width primary action and same full navigation inventory.
TOPOLOGY: guest contact/shipping details, delivery plus distinct billing, payment review. Existing API requires recorded accepted terms before issuing Stripe credentials: preparing the Payment Element stays inside the third named step, then the actual provider amount is confirmed. Collection skips shipping fields and requires a separate billing address. Old API without delivery capabilities retains legacy quote requests. Published public Store flag stays off.
MOTION: scoped useGSAP lifecycles. MUI Modal/Fade owns cart focus entry/enforcement, protected background, Escape/backdrop dismissal and opacity; GSAP owns cart clip, position and backdrop blur. Restore trigger focus after exit. Reduced motion also removes cart blur. Step exit190ms, content reveal600ms stagger28ms, container height480ms, progress750ms, billing500/320ms, cart600/300ms, confirmation stroke800ms. No animations per keystroke. Reduced motion removes transitions. Bounded layout height for a form/disclosure is deliberate; progress and stage positions use transforms. Context cleanup preserves interruption/unmount.
CONTENT: all titles, prices, quantities, delivery methods, fees, parcel partitions, estimates and legal versions come from existing APIs. Shared direct public-image component and server-provided responsive URLs. Never confirm payment from the browser; preserve pending, payable, failed, expired and paid-unfulfillable states. Existing guest identity, accepted-terms evidence, attempt idempotency and cancellation protocol remain unchanged. Lock cart once quoting/preparing/payment freezes its reviewed contents.
